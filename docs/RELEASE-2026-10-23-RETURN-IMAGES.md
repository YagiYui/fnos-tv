# 返回页面图片闪现修复

日期：2026-10-23（Asia/Shanghai）。本批处理用户在上一批目录浏览发布后的缺陷反馈。

## 原因与修改

路由离开后销毁页面与图片节点。原 vue-lazyload 的监听器每次初始化先渲染透明 loading 图，再经可见性检查使用真实图片，即使内部已记住该 URL 也会先占位。首页继续观看重新从 null 请求、详情重新从空对象请求，以及片库后台验证时整网格透明度降至 0.65，叠加为返回时“从无到有”的刷新感。数据缓存和浏览器图片缓存本身不能阻止这些渲染行为。

- 全部浏览页图片通过 `MediaImage.vue` 首轮绑定真实 src。冷图使用浏览器原生 lazy；会话内最多记住 512 个成功显示 URL，重建时提示 eager，详情主图始终 eager。图片字节仍由浏览器缓存管理，已有缺图路径保留；停止注册旧懒加载插件，未调整依赖锁文件。
- 首页继续观看与最多 16 条首页／详情展示快照保留在当前账户内存，返回先恢复已有内容和内容容器位置，再后台请求更新；刷新失败保留内容，成功空列表正常清空。首页栏目刷新失败可显示提示同时保留已有卡片，片库后台验证不再整体变暗。
- 详情展示快照不缓存 play/info 返回、播放票据或播放器实例。播放信息重新请求，保留电影 ID 与显式选集路由；季、集和人员请求在元数据之后并发取得。详情内切换只在实际路由提交后加载，离开取消请求并丢弃旧响应。
- 快照不写浏览器存储；退出、登录页和换账户清空，revision 阻止 A→B→A 期间旧请求回写。图片已被浏览器回收或 URL 改变时仍需正常加载；刷新整页或快照超限淘汰后不承诺恢复历史展示。
