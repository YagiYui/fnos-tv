# 可配置弹幕来源

## 范围与使用

播放器设置增加“弹幕来源与偏好”，现有弹幕搜索也提供入口。管理员可启用／禁用并排序六个内置平台，分别控制 360／豆瓣候选搜索入口，设置服务默认首选及回退；自定义服务最多八个。普通账号只读服务配置，在允许范围内保存个人偏好。没有自动接入未经提供的第三方服务。

默认按顺序选首个非空来源，失败／空结果是否回退可配置；不继续默认合并全部平台。明确绑定的链接失败不悄悄改绑。旧共享单集 URL 继续读取，新界面的绑定写入独立账号存储，不迁移或冒充原记录的所有者。

账号偏好、当前季度／影片、单集覆盖按“单集 → 季度／影片 → 账号 → 服务”生效。季度绑定只保存明确分集编号的映射，缺集不猜测；清除某范围覆盖回到上层设置。来源变化只重载弹幕，保留视频进度／暂停，清空旧队列，取消请求并拒绝迟到结果；表情按实际选中平台读取。

## 接口与持久化

- `GET/PUT /danmu/sources`：验证官方 user/info，使用当前官方公开代码已确认的 is_admin 标志授权修改。配置为 data/danmaku-sources.json，版本检查防止覆盖其他页面修改，文件 0600，原子替换、跨进程锁；读取损坏配置时拒绝，不静默重新启用默认源。
- `GET/PUT/DELETE /danmu/sources/preferences`：账号从服务端验证结果取得稳定标识后散列，调用者不能指定账号。个人记录位于独立 data/user-state.sqlite3，不修改既有 data.db 表或历史共享来源。季度／单集写入先通过官方 item 接口核实媒体访问权限。
- `POST /danmu/sources/check`：管理员检查已保存服务，分别返回连接／搜索、分集、弹幕阶段；搜索为空不能宣称后两项已验证。管理界面展示各来源最近结果，状态不保存原始错误或请求地址。
- 共享请求包装器、平台请求基类和 B站直连入口在发起网络请求前重新检查启用状态；已经发送的响应不因禁用而伪装撤销，前端代次保护防止旧数据应用。

## 首批自定义协议

适配自托管 Dandanplay v2 兼容服务：`GET /api/v2/search/anime?keyword=...` 的 animes，`GET /api/v2/bangumi/<animeId>` 的 bangumi.episodes，以及 `GET /api/v2/comment/<episodeId>?format=json` 的 comments（m 文本、p 的秒数／模式／颜色）。依据为 [兼容服务维护者接口说明](https://github.com/huangxd-/danmu_api/blob/main/README.md) 和本项目现有 Dandan 路由，使用隔离 HTTP fixture 验证完整流程。保留 64 位标识的字符串形式，过滤无效时间、模式和颜色。

服务地址不包含 /api/v2 后缀或鉴权；Bearer／路径令牌另行保存，留空保留、明确勾选清除，界面只返回 has_token。路径令牌由后端组合，不回显。官方弹弹play的 AppId／签名模式与自托管兼容服务不同，本适配器没有冒充其官方授权；相关区别见 [官方接入说明](https://doc.dandanplay.com/open/)。异步分片和其他协议暂未包含。

HTTP／HTTPS 限定，解析地址后检查并固定目标 IP，保留 Host／TLS SNI 和证书验证，不读取代理环境、不跟随重定向。内网必须管理员显式允许，链路本地、保留、广播／组播及未指定地址拒绝。请求限制 2–30 秒和 16 MB；不把远端响应或凭据写入日志／诊断。
