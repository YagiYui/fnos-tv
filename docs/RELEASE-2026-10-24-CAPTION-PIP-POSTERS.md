# 带字幕画中画、PotPlayer 唤起与封面调度

用户本轮明确要求：外部直接唤起 PotPlayer；待看统一返回首页；画中画必须显示字幕，弹幕可选；跳至电影第 7 页后封面分批等待过长。

## 已实现

- PotPlayer 图标与首选播放器动作改为既有 `potplayer://` 协议入口，单独保留 M3U 下载及 HTTP 地址；浏览器可能要求确认打开应用。只读核对本机已经存在协议注册，不修改注册表、不安装启动器。网页无法可靠判定本机应用是否真正打开，保留可用备用方式。
- 待看按钮文字和行为都统一“返回首页”，从详情或直接地址进入也不回到详情。
- 支持 Document Picture-in-Picture 的安全桌面环境使用文档浮窗，移动同一个 ArtPlayer 根节点及视频、普通字幕、ASS／PGS 画布和弹幕；复制样式、提供播放／暂停、进度和返回控制，关闭、路由、账户及销毁清理。跨文档媒体需要重新就绪时恢复进度／倍率和暂停状态，不重复创建影片会话。禁用当前视频的纯视频原生浮窗入口；不支持带字幕浮窗时明确提示桌面浏览器，不静默降级成无字幕浮窗。
- MediaImage 对可视区域及附近图片使用共享四并发，重试等待不占请求槽，取消／切页释放队列与观察器；有响应超时上限。自动退避由累计 28 秒缩为约 5.75 秒，仍有次数上限、单张与整页重试。按官方带目录 poster 路径构造首页／片库地址，只对旧裸文件名保留默认目录，避免额外拼入静态目录；未引入服务端共享私有封面缓存。

## 封面证据与边界

变更前只读抽样约 90 分钟图片日志，约 1263 个请求包含 325 个 404；118 个图片标识在同一实际路径先后出现 404 与图片 200。记录的服务端请求 p50 约 8ms、p95 约 0.63 秒、最大约 1.99 秒。这些不包含浏览器排队和外网传输，不能当作用户端到端速度。未发现“规范路径成功而重复目录失败”的成对证据，不把静态目录修正宣称为已证实根因。未登录探测得到鉴权类 JSON，不能用其 HTTP 200 冒充有效图片或性能结果；没有获取或索取用户凭据。

本批针对已证实的瞬时失败与前端并发／重试行为处理。真实第 7 页仍需用户原设备复验，若持续失败应按时间继续核对官方图片生成与外网链路，不以模拟结果宣称真实加速比例。

## 验证

完整前端 51 项通过，1 项缺少真实 PGS `.sup` 素材跳过；构建通过。独立 Edge 使用合成 API／视频进行真实 Document PiP 验证：原生 MP4 与 Hls.js、普通字幕、实际 libass-wasm ASS 画布、浮窗弹幕、拖动、播放／暂停、关闭／返回时状态与账号变化清理。浮窗包含同一个视频，页面异常为 0。可视第 7 页模拟冷 404 恢复、四并发与规范路径通过；约 0.5–0.8 秒仅是 80ms 本地 fixture 的结果，不能外推为正式速度。PotPlayer 链接及 M3U 备用 DOM 检查通过，自动化不启动本机播放器；实际协议唤起／中文标题和真实 PGS 待验收。

官方实现依据：[Document Picture-in-Picture](https://developer.chrome.com/docs/web-platform/document-picture-in-picture) 支持整段 HTML、复制样式及关闭还原；[BitComet WebUI 本机播放器文档](https://wiki.bitcomet.com/webui-invoking-the-local-video-player/) 说明已注册自定义协议与浏览器确认。本批不采用其注册脚本。
