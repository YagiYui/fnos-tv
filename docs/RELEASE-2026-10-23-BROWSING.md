日期：2026-10-23（Asia/Shanghai）。本批推进 TODO 的 C 和 F1.2 中目录浏览这一组目标，不代表 C／F1.2 全部完成。

## 已实现

- 首页先取得媒体库目录，影片栏目进入可见范围时再请求首批 21 条；保留原轮播和卡片列数，以同列数骨架占位。栏目按目录顺序展示，单库错误可重试；不支持 IntersectionObserver 时回退为受并发上限约束的加载。数量统计改为后台请求，失败不再阻断库目录和影片加载。
- 所有可见栏目共享最多 3 个请求并发，合并相同在途任务；保留 60 秒账户内存缓存和最多 64 条缓存记录。进入搜索或离开首页取消未完成任务，成功缓存保留；换账号或退出时清除。迟到响应和旧请求收尾不能覆盖新数据或加载状态。
- 片库按活动账号与媒体库分别保存现有排序、页码、当前页结果和 Naive UI 内容容器位置，最多保存 12 个片库。媒体结果只在内存中保留，不写入 localStorage；页面刷新后不承诺恢复。
- 详情／播放器返回片库时先恢复已知页面，再通过原 `POST /v/api/v1/item/list` 验证同页。刷新期间用户继续滚动时，不强行拉回旧位置。切库与新查询取消旧请求；保存页码因库内容减少而失效时回退到有效页。排序在各片库独立保存，不再改变首页全部媒体库的排序。
- 未新增筛选请求字段，未猜测搜索分页。请求仍沿用已有账户鉴权和列表参数，未增加写入媒体状态的接口。
