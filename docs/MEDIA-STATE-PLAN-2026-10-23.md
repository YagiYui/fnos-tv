# F1.3 收藏与观看状态实施准备

本阶段在片库筛选之后推进。已完成请求契约、独立数据层与回归；尚未接入页面或部署。线上继续使用前端 `f0e62cf`，本次没有更改真实收藏或观看状态。

## 已完成

- `media-actions.js` 实现收藏增加／撤销、已看增加／撤销的准确方法和单项 JSON 请求体，沿用共用账户请求层，不自行管理或保存凭据。成功空 data 可确认；业务拒绝不会变成乐观成功。
- 同一账户、操作类型和媒体 ID 的相同在途操作复用一个请求；反向或不兼容操作明确拒绝，不隐式排队。没有自动重试写入。
- 单项操作默认读取官方 item 最新状态。返回包含服务器确认、规范化最新标记、错误和警告；写入已确认但读取失败时仍保留“已保存”事实，拒绝／超时后的界面应以刷新结果为准，不猜测服务端回滚。
- 数据层提供带账户与生命周期 revision 的缓存失效回调，写入结果不确定时也通知重新验证。缓存回调故障不伪装为服务器写入失败；实际应用中的首页、搜索、详情与列表缓存协调尚待页面接入时实现。
- 账号退出或更换时中止旧请求并丢弃旧回调；A→B→A 的旧结果不能应用到新生命周期。请求 abort 不等于已经撤销服务端操作，重新进入页面仍需读取官方状态。
- 整季助手接受明确分集 ID 列表，发送前整体校验并去重，最多 1000 项、两个并发；逐项记录服务器接受、失败／未确认和未执行。停止不再启动新任务，已发出的请求收尾后汇总；账号切换的旧批次被标记过期，新账户可以立即开始独立操作。分集内容最终需由调用页面整体刷新核对。
- 收藏列表读取采用官方分页、排序与 tags，标签范围使用 is_favorite=1；不发送虚构片库 ID、内部 isFavorite 字段或未经核实的批量写入结构。
- 完整前端回归 29 项通过、1 项真实 PGS 素材项跳过；构建兼容检查通过，补充参数／账户批次检查也通过。新增检查覆盖请求结构、重复点击、拒绝／超时、接受后读取失败、缓存异常、生命周期、两并发、部分失败、停止、新账户批次及收藏查询。

## 待确认的页面范围

推荐首批在现有详情布局加入收藏切换，电影和单集加入已看／未看；侧栏增加“收藏”，复用现有片库筛选、分页和返回恢复。整季先展示本次将处理的明确集数并确认，再逐项更新、展示进度和部分失败结果。可选缩小为先做详情操作、收藏列表稍后。

独立“待看”与官方收藏含义不同，未发现对应接口时保持未实现。季／整部剧的服务端递归行为也没有证实，不能猜测仅提交父级 ID 的效果。超过当前批次上限、分集列表未完整加载或状态字段缺失时，不直接发出声称覆盖整季的操作。

用户已收到范围选择；主仓库 TODO 要求“涉及布局与交互变动时先确认具体方案”，确认后才修改页面、实现缓存协调、执行真实组件回归并带备份发布。目前仅有数据层能力，不将其标为已上线或 F1.3 完成。

## 页面接入后的验收

1. 电影及单集新增／撤销状态后刷新保留，失败不伪装成功，按钮忙碌时不重复提交。
2. 从详情返回首页、搜索、片库或收藏时，状态与筛选结果重新验证；取消收藏后正确移出收藏，已看修改后正确影响已看／未看筛选与空页回退。
3. 季操作的目标集合清楚可核对，取消不启动新写入，汇总能区分接受、失败／未确认、未执行；真实接口反馈与最终刷新一致。
4. 两个真实账户分别验证个人状态及可见范围；账号切换、快速切片与离开时不串用结果。
5. 手机／平板分别检查控件、确认提示、焦点与进度展示；保留原视频播放、字幕、弹幕和返回能力。
