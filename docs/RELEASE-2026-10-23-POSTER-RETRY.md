# 收藏首次进入时海报空白修复

日期：2026-10-23（Asia/Shanghai）。本次处理用户反馈“第一次点击收藏时，未刷新没加载的图片”，不将此反馈作为 F1.3 整体验收通过。

## 定位与修改

生产安全访问日志显示，17:19 首次 favorite/list 请求之后 3 个海报请求返回空 404；随后访问时其中相同图片路径返回 200。日志不含查询参数，因此不能证明两次缩略图尺寸完全相同，也不能断定上游生成的具体过程。已确认前端 MediaImage 仅处理成功 load，失败后不再自行请求，必须重新挂载或刷新才有机会恢复。没有发现该时段普遍的图片链路不可达。

前端共用组件增加有上限的错误恢复：初次请求失败后分别等待 500、1500、3000ms，最多增加 3 次请求；成功、源地址改变和组件卸载取消待执行重试。用当前元素身份与地址拦截旧图片迟到事件，不向另一张图片延续重试。

仅本站 /fnos/v/api/v1/sys/img/ 重试增加次数参数绕过失败响应缓存，原查询与片段保留；自定义或签名图片地址保持原样，通过重新创建元素重试。成功记忆原始 URL，延续原有冷图懒加载、返回时已成功图片优先加载和 512 条有界 URL 提示。该处理不保证永久不存在或鉴权失败的图片能够恢复；3 次仍失败后停止，不循环请求。未改图片路径拼接、收藏接口、个人状态、后端配置或数据库。
