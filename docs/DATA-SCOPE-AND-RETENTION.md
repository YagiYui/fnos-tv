# 媒体授权与数据保留

## 授权与共享边界

所有授权以当前请求的飞牛账号为准，不能用 NAS 服务账号替代媒体访问权限。读取共享跳过片段／弹幕链接时核查官方 `item/{guid}`；季度与分集必须有真实 parent_guid 关系。只有官方 user/info 的 is_admin 为真或整数 1 才能修改旧家庭共享配置，旧数据不臆测归属。普通用户使用个人弹幕来源偏好，不改其他家庭成员的配置。

`/api/play` 必须携带 item_guid、media_guid、path；先确认媒体访问权，再从官方 stream/list 中精确匹配文件 GUID 和路径，之后才能调用现有 NAS 挂载凭据。Alist 登录与获取链接使用请求独享 Session，避免并发挂载混用全局 host/token。失败时网页保留已创建的飞牛播放链接。共享读取和直链响应均 no-store。

官方进度成功后才保存辅助记录；新增媒体范围验证失败或本地存储故障不隐藏官方成功、不自动重试 POST。DELETE 仍走既有官方代理。辅助跳过片段记录仍是家庭共享学习数据，不冒充个人观看历史。

自动匹配不再插入旧共享 videoConfigUrl；只在已登录、已验证媒体的请求中保存个人自动缓存，键含账号、来源配置版本、媒体／季度及匹配参数，10 分钟过期，每账号最多 128 条。配置版本变化不复用旧缓存，缓存失败不阻断视频，清理只作用于 auto-danmaku 缓存，不删除个人绑定。电影使用弹幕第 1 集，兼容官方 Movie 的 episode_number=0。

## 保留策略

| 数据 | 默认策略 | 清理与回退 |
| --- | --- | --- |
| 官方观看历史与媒体 | 由飞牛维护 | 本工具不读取或删除官方历史，不删除媒体 |
| 辅助 record 表 | 默认永久保留，不自动清理 | 管理操作可选择 30–3650 天，建议先预览 180 天；过期记录减少后历史跳过片段学习样本也会减少 |
| 旧共享配置 | 永久保留 | 不自动去重、不批量转成某个用户数据 |
| 个人偏好、待看、来源绑定／观察 | 按账号保留 | 用户明确重置或移除；已有每账号数量与容量限制，不按缓存 TTL 删除 |
| 自动弹幕匹配缓存 | 10 分钟、每账号 128 条 | 在匹配时仅淘汰该缓存类型，来源版本隔离 |
| 字幕缓存、临时播放票据 | 沿用既有容量／过期策略 | 与辅助历史清理分开，不能互相替代 |

生产历史本轮不执行删除，也不安装 cron。只读预览：

```sh
python scripts/record_retention.py /path/to/data.db --days 180
```

明确需要清理时才使用以下操作；必须指定独立备份目录。它在 SQLite 写锁期间先用在线备份 API 生成完整数据库副本并检查，再在同一写事务删除符合截止时间的 record 行；失败回滚。零值、非数值、毫秒或未来时间保留供单独核查，不猜测修复。输出只包含数量、时间范围和备份路径，不输出媒体标识或文件名。

```sh
python scripts/record_retention.py /path/to/data.db --days 180 --apply --backup-dir /path/to/private-backups
```

不做 VACUUM，不修改其他表。紧急恢复应停止本服务后在副本中合并被删 record 行；不要直接覆盖线上数据库而丢失清理后的新进度或共享配置。发布回退仅恢复代码、服务定义及静态入口，保留实时数据；现有索引 migration head 不变。
