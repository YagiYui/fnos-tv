# TODO C：排队请求的账户归属

八项实测问题正式发布后继续账户隔离：Axios 拦截器之前在异步执行时读取 Cookie，排队中的进度上报也只保留媒体数据。若等待期间切换账号，旧进度可能带上新账号凭据；旧请求的登录失效响应还可能把新账号转回登录页。

本批在调用认证请求时立即捕获凭据，进度队列同时保存原账号／凭据，按账号与媒体键分别合并。请求仍在原作用域中收尾；旧账号失败不改变新账号登录状态，也不显示在新播放器上。凭据仅留在内存中，通过原有请求头发送，不写进进度 JSON、日志、文档或持久化存储。保持队列最多八项、串行发送及错误隔离。

实际 Axios 与播放器源码回归复现 A 的请求延迟、同片排队后切换 B、A 返回登录失效，再验证三次原始进度分别归属 A／A／B，不串账号、不误注销、不弹出旧错误。完整前端 49 项通过、1 项真实 PGS 样本跳过；构建及上一批八项独立浏览器交互回归通过。
