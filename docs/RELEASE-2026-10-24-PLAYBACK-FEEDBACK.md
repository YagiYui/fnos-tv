# 播放恢复验收反馈修复

日期：2026-10-24（Asia/Shanghai）。用户报告：脱机时缓冲仍可播放却立即弹失败；PotPlayer 入口下载 m3u，复制地址不能播放；首次登录没有继续观看。本记录是 F2.1 的缺陷修复，不将上一批自动化通过视为真实验收已完成。

## 证据与修复

首页在 setup 捕获登录前的 userKey 和快照 revision，账户初始化完成后只清空列表，没有绑定新账户重新读取。正式访问日志中 play/list 成功不能证明结果被页面接纳。现在快照 store 提供响应式账户，首页在账户生命周期改变时取消旧请求、绑定新账户和 revision、恢复新账户快照并重取继续观看；未取得账户前不抢发列表请求，旧账户迟到响应继续丢弃。

HLS 的后续资源网络错误不等于已缓存媒体无法解码。新增缓冲检查：网络致命错误时，如果当前区间仍可播放则继续使用缓冲；耗尽、跳转到不可用区域或原生／解码错误时才显示恢复卡片。恢复网络可恢复当前 HLS 的加载，收到新片段后清理待处理错误；换源／离开清理定时器与监听器。没有离线事件直接暂停视频的处理。

PotPlayer 图标下载标准 m3u 是已有明确设计，历史上用户要求撤回 Windows 协议修改，不能将该行为当成新故障再修改注册表。实际打开失败的线上证据为：临时地址创建成功，资源请求随后连续 502；直接检查对应官方清单得到 410，而临时票据仍未到期。受控独立会话中，空闲约 65 秒已失效；轮询主清单、checkPlayLink 或 transcodeStatis 均未保证存活，独立 FFmpeg 也只解码约 68 秒后结束。没有用伪造播放进度续命或写入用户观看状态。

重新核查当前官方公开代码，原文件地址使用 `/v/api/v1/media/range/<media_guid>`。当前账户只读分段探测实际返回 206、正确 Content-Range 和文件字节，不需要转码 play_link；官方原文件 HEAD 返回 501。新后端临时票据可绑定一个严格 32 位 GUID 的原文件路径：先使用既有签名工具请求当前 item_guid 的官方流列表，核对账户权限和文件归属，再严格校验单字节 206／Content-Range，发放无浏览器 Cookie 的有时限地址。票据只允许本文件，禁止其他资源和附加查询；Range／If-Range 转发，HEAD 使用单字节 GET 提取元数据，凭据仅保存于原有私有 tmpfs，旧 HLS 票据保持兼容，410 不再一律伪装为 502。

Windows 外部播放优先使用这个原文件地址，不新建转码会话，由 PotPlayer 等外部应用负责位置、音轨和字幕；m3u 和可复制 HTTP 地址都指向同一受限票据。其他平台沿用独立的 HLS 会话，不覆盖网页播放会话。没有修改 Windows 协议、注册表或关联。原文件模式不承诺网页失败位置自动传入外部应用。

## 回退

只回退最后的账户清空保护，可按 [静态回退流程](../deploy/README.md) 使用 final 备份的 web-before/ 与 previous-web-manifest.json，恢复至 `eb1d4ba`。撤回本批全部前端修复则使用首批静态备份 `...-083316/web-before/` 与其 previous-web-manifest.json；按本批 release-manifest.json 的 11 个 source_files 从该备份 frontend-before/ 逐项恢复，本批新 external-session.js 和对应测试在旧源码不存在时仅移除这两个文件。不要整仓覆盖。final 备份的 original-web-manifest.json 及 rollback-rehearsal.json 记录整批前版本校验和演练结果。

如需回退后端，先恢复旧前端，另备份当前补丁，再将后端备份 `...file-proxy-20261024-083146/external_play.py` 的字节写回原挂载文件，保留 inode；对独立流 master 发 HUP，对普通 API master 发 TERM，由已核对的 supervisor autorestart 重新启动。等待本地 Flask 的无鉴权 external-play POST 返回 401／code -2，再验证健康；不能只探测官方版本代理作为 Flask 就绪判断。已发放的原文件票据在旧后端不兼容，需从恢复后的页面重新获取链接。整个回退不恢复数据库或覆盖新播放进度。
