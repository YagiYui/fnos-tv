## 回退边界

旧镜像不认识新 Alembic revision。不能只把 image 改回去后直接启动，也不能为了回退丢弃发布后的新观看记录。

1. 核对当前仍为本次镜像及 `add_lookup_indexes`，若已发布其他版本，先重新评估，不套用旧步骤。
2. 停止 fnos-tv，额外保存此时的 Compose 和一致性数据库副本。
3. 用本次新镜像、无网络、仅挂载已经停用的服务 data 目录，执行 `python -m alembic downgrade create_initial_tables`。这个目标只撤回本次四个索引并回到旧 head，业务表和行保留；**不得继续 downgrade 到更早 revision**。该操作已在副本上验证。
4. 原子恢复本备份的 `compose.service.yaml`，执行 `docker compose -f /vol7/1000/docker/docker-compose.yml config --quiet`，再只以 `up -d --no-deps --pull never fnos-tv` 恢复原镜像。
5. 检查健康、Nginx、业务行与无关容器状态。本次没有更换网页，不需回退静态文件。常规镜像回退不覆盖旧 data.db；它仅作为异常情况下的独立灾难恢复副本。

发布脚本对失败自动执行相同的索引版撤回和旧镜像恢复，未用旧数据库覆盖新业务行。副本演练不等于人为切换过生产旧版；本次生产升级正常，未触发自动恢复。
