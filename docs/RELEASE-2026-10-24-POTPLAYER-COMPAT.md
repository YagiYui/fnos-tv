# PotPlayer 下载颜色与损坏地址保护

用户反馈下载文字在深色弹窗中颜色不对，直接唤起后地址的 `https://` 变成 `https//`，播放器提示文件不存在。此前对原始 href 的检查没有覆盖浏览器实际传给系统的解析结果，不能作为直接唤起成功的证据。

## 处理结果与限制

下载入口改用 Naive UI 的链接按钮，文字采用文档主题正文色并显示下划线，保留下载文件名、M3U 内容、票据和原文件接口。普通／悬停／焦点状态在深浅主题都清晰可见。

直接链接继续沿用原生 PotPlayer 认识的旧协议形式，但生成后比较 URL 解析结果；地址会被改写时返回不可用。图标置灰、首选直接链接不显示，并给出下载 M3U 或复制完整 HTTP 地址的提示。支持无损传递的解析器仍可显示既有入口。

这只是防止发出已知损坏地址，不是解决当前浏览器与原生协议的兼容性。没有修改注册表、播放器安装、浏览器启动参数，也没有安装协议启动器。直接唤起需求仍未完成，后续不能把入口保护或文件可播当成直接唤起成功。

## 验证

- Node 回归重现 HTTP／HTTPS 内层冒号丢失，覆盖非默认端口、中文编码文件名与查询参数；确认不返回损坏链接、M3U 保留完整地址。外部播放与媒体偏好两个相关回归通过。
- 独立 Edge 加载实际 VideoPlayer 和 Naive 主题，深浅两种主题各验证普通／悬停／焦点颜色，对比度分别约 12.2 和 16.1；检查浏览器真实下载的 M3U 内容，以及普通、首选入口均不产生损坏的 PotPlayer 链接，页面异常为零。
- 本机使用 `/new`、静音参数启动独立 PotPlayer 实例请求回环地址的合成视频，只终止该次测试启动的进程，保留用户原播放器进程。原始旧格式可请求视频；opaque、额外斜线、编码冒号、完整编码等候选均未产生视频请求，故未采用这些候选。此检查不代表真实影片长时音画验收。
- 构建通过，仅有既有大包体积提示；真实设备颜色及 M3U 长时播放仍按 F10／R04 记录。
